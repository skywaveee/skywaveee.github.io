# 让知识、讨论和你的判断积累下来

AI 可以先整理比你读过更多的材料。Mindspace 希望这些材料进入研究，也让你在关键判断处逐渐形成自己的理解。

## 知识怎么放：通用结构，学科自己长

建议保留四种内容：原始来源、单篇摘要、专题梳理、共同讨论。目录名可以按学科调整。下面是 AI 研究的起点，不是所有人必须遵守的分类法：

```text
knowledge/
├── README.md                 # 入口，也可以链接已有的外部知识库
├── sources/                  # 单篇论文摘要；链接 PDF、代码、版本
├── topics/                   # 按问题组织：SFT、OPD、RL、Agent……
├── co-reading/               # 对某篇论文或某个概念的多轮讨论
├── methods/                  # 适用条件、实验做法、失败经验
├── READING.md                # 希望 AI 怎样读材料、怎样解释
└── UNDERSTANDING.md          # 我关注什么、卡在哪里；链接到讨论
```

PDF 可以放在自己的文献目录，也可以和摘要相邻；只需在来源卡留下稳定路径或链接。已有知识库就链接过去，不必搬家或复制一套。不同学科替换主题，例如社会科学的方法与测量、历史研究的史料与解释；来源、证据、局限和修订依据仍保留。

专题不是多篇摘要的拼接。它应该回答一个问题：有哪些主张、证据能否比较、冲突在哪里、对当前研究有什么含义。

## Understanding 从哪里来：从讨论里留下来

你追问一篇论文的某个设计、反复讨论一个公式、用自己的例子解释方法，这些都是理解的过程。AI 可以把讨论整理到 `co-reading/`，保留你的问题、得出的解释、仍然不确定的部分及引用。

`UNDERSTANDING.md` 只是一张轻量索引：当前在意什么、什么还不清楚、需要时先学什么，链接回详细讨论。不要再复制一遍论文摘要，也不用给所有收录论文逐篇打“掌握等级”。

只记录你实际表达的理解。AI 的长篇讲解本身，不构成你已经掌握的证据。你也不必每次接受测验；确实需要检查关键理解时，再用一个例子或对照讨论。

## 多聊几轮以后，写回哪里

| 讨论带来的变化 | 主要写回位置 | 一个例子 |
| --- | --- | --- |
| 弄清一篇论文的设计 | 该论文共读笔记 | 为什么需要这个对照组 |
| 发现原摘要有误 | 修正原摘要，留下来源和修订原因 | loss 的适用条件之前写宽了 |
| 形成跨论文的认识 | 专题材料 | 几种蒸馏方案的数据条件差异 |
| 出现候选研究想法 | ideas，链接来源与验证思路 | 某个收益可能来自数据分布 |
| 发现稳定的阅读偏好 | READING.md | 我更希望先看动机与关键对照 |
| 当前问题影响项目选择 | projects / decisions | 为什么先做这个消融 |

一次追问先留在讨论里。只有你明确说“以后都这样”，或反复出现且得到你认可的偏好，才沉淀进阅读规范。不要因为某次问了公式，就把每篇论文都改成长篇公式推导。

## 证据质量和我的理解，是两件事

来源要区分“原文未核”“论文报告”“我们复现验证”；理解则记录你的实际问题与解释。你没读过的可靠材料仍然可以被 AI 用来设计方案，但关键假设、引用位置、适用边界需要说明。

更多参考材料只有经过相关性和证据筛选才有价值。不要按材料数量投票，也不要把相互转述的文章当成多份独立证据。

## 需要时再学，先学影响决策的部分

当你正在决定实验方向时，AI 应指出：**这个判断依赖哪个概念？理解它会改变哪个选择？现在花时间学的理由是什么？**

例如准备比较两种训练方案，先弄清数据构造和评测是否公平，通常比先补齐整条领域发展史更贴近当前问题。这是按任务安排学习，不是永远把判断交给 AI。

## 一次工作的闭环

开始先读 `HOME.md` 和 `WORKFLOW.md`，按需恢复当天记录与项目状态。研究过程中保留来源、反例和局限。收尾时只更新发生变化的记录，同一事实有一个主要位置，其余链接过去。

建议、实现、运行、验证分别写；没有实际证据不标记完成。个人随记保留语气。重要判断改变时，保留旧判断的依据和新证据。

v0.1 提供这个文件与协作流程。实验自动执行、搜索和评测还需要各领域自己的工具与反馈机制，并没有随模板自动实现。
